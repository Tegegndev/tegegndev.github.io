WSU Student Cafeteria Milling System

A digital meal verification system designed for Wolaita Sodo University, modernizing cafeteria logistics by replacing paper meal cards with real-time QR/barcode scanning, fraud prevention, and an executive React admin dashboard.

1. The Problem: Manual Ticking & Food Waste

Wolaita Sodo University serves thousands of residential students across multiple cafeteria sessions daily (Breakfast, Lunch, Dinner). Prior to digitization, the university relied on manual paper punch cards and student ID visual checks. This approach suffered from several chronic challenges:

  • Duplicate Meal Abuse: Students sharing cards or re-entering cafeteria queues during the same session, inflating food supply demands and causing food shortages.
  • Slow Queue Throughput: Physical card verification caused bottleneck queues of hundreds of students under high peak meal times.
  • Lack of Real-Time Auditing: University management had no immediate data on how many meals were consumed per shift, making daily budget allocation and grocery planning imprecise.

2. Architecture & Solution Overview

The system consists of two tightly coupled components backed by Supabase:

System Topology:

Mobile App (Flutter) for cafeteria line officers → Supabase Cloud Database with Row Level Security → React Web Admin Dashboard for university managers.

Core Capabilities:

  • Rapid QR / Barcode Ticking: Camera scanner identifies student QR codes in under 200 milliseconds, validating active enrollment and session eligibility.
  • Duplicate Prevention Guard: When an ID is scanned, the database atomic transaction verifies if the student has already ticked for the current meal session. Duplicate attempts trigger an instant visual and acoustic alert.
  • Ethiopian Calendar (Ge'ez) Integration: Native date calculation aligning meal attendance records with the Ethiopian fiscal and academic calendar.
  • 4-Language Localization: Full UI support for English, Amharic (አማርኛ), Afaan Oromoo, and Wolaytta (Wolaitta Dootta).
  • React Admin Dashboard: Comprehensive analytics reporting showing hourly meal consumption, attendance rates, and cafeteria efficiency trends.

3. Technical Challenges & Solutions

Challenge A: Sub-Second QR Validation in Low-Connectivity Environments

Dining halls located in basement levels or crowded campus sectors frequently experience intermittent cellular connectivity, which would stall cloud API calls.

Solution:

Implemented offline optimistic caching. The Flutter client preloads active student verification hashes at the start of each meal shift. Scans are validated locally in milliseconds, and check-in logs are queued and synchronized with Supabase once network connectivity resumes.

Challenge B: Multi-Language Font Rendering Across Regional Devices

Rendering Ethiopic scripts (Amharic and Wolaytta) alongside Latin scripts without layout shifts requires careful typography budgeting in Flutter.

Solution:

Configured unified Google Fonts (Noto Sans Ethiopic and Space Grotesk) with automatic fallback handlers, ensuring crisp glyph rendering across varied Android OS versions.
